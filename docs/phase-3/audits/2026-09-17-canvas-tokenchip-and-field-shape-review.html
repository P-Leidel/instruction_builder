InstructionCanvas: one small render loop calling it

Problem: the token's whole drag/select decision tree lives inside an inline onPointerDown closure three JSX levels deep — there's no TokenChip module to delete, so nothing concentrates when you imagine removing it.

Solution: extract a TokenChip (and a matching StepCard for the step-handle drag closure at lines 371–391) that owns pointer wiring and exposes only selection/move/remove callbacks.

  • Leverage: one interface for select, move, and remove — three call sites collapse to one
  • Locality: the drop-target equality guard moves next to the drag logic it protects
  • Testability: "a drag ending over slot X moves the token" becomes reachable without Playwright
This is the 2026-09-15 canvas-followup review's candidate #2 (docs/phase-3/progress/architecture-svgbutton-extraction.md: "splitting <StepCard>/<TokenChip> … remains unexplored"), deliberately deferred once already. Re-surfacing it because the file hasn't shrunk since — it's still 585 lines after the SvgButton extraction closed out the sibling candidate.

Deepen the collapsed/popover shape into one CollapsibleField

Worth exploring in-process

src/components/DurationField/DurationField.tsx (lines 160–214) · src/components/TokenDetails/TokenDetails.tsx's QuantityRow (lines 145–197)

Before — two stacked bands, same chrome

DurationField: trigger + field-popover-anchor + FieldPopover + Save/Cancel
QuantityRow: trigger + field-popover-anchor + FieldPopover + Save/Cancel

~90 lines of identical structure, differing only in form contents. Both now also expose an identical controlled editing/onEditingChange pair just so TimeAndQuantityRow can keep them mutually exclusive.

After — one thick band

CollapsibleField

{ trigger label, editing, onEditingChange, children: form }

DurationField and QuantityRow each shrink to just their form body, passed as children.

Problem: the trigger/popover/collapsed-vs-editing chrome is duplicated across two modules that already share a controlled-editing interface in practice.

Solution: pull that chrome into a CollapsibleField module; DurationField and QuantityRow become thin adapters supplying only their form.

  • Interface shrinks: one popover/focus-trap wiring, not two
  • Locality: a future third field-editor gets the shape for free
  • Two adapters (duration form, quantity form) justify the seam
Goes against DurationField.tsx's own recorded rationale (lines 39–42): "a four-number duration and a two-field amount+unit form don't share enough shape to be worth a common prop surface." Worth reopening because that call predates TimeAndQuantityRow, which now forces both modules to expose the same controlled-editing contract anyway — the shared shape it argued against already exists.

Problem: splitQuantity silently falls back to defaults for any label it can't recognize (an older schema, a future unit-list change) — the deletion test already leans toward "concentrates."

Solution: store amount/unit as fields on the attachment; join only for display.

  • Removes a silent-fallback failure mode entirely
  • Locality: no more re-parsing a display string to edit it
Already tracked in docs/known-issues.md and deliberately deferred to Phase 4 task 32 — the audit's own prior assessment rated it weaker than other candidates. Top recommendation

Give the canvas a TokenChip module

It's the only candidate with zero locality today — the drag/select decision tree for a token has no seam separate from the render closure it's tangled in, so it can only be exercised through Playwright. It was already identified and deferred once; deferring it a second time lets InstructionCanvas.tsx keep growing every time canvas interaction changes.
