1. Name the two-stage select/drag decision

Strong in-process

Before

After

Problem: the click-vs-drag decision lives twice, inline in JSX closures, and only the Playwright driver exercises it.

Solution: extract one function that turns (wasDrag, isSelected, dropTarget) into an outcome; both onDrop handlers call it instead of re-deriving it.

  • Locality: the select/drag rule exists in one place, not two independently-maintained copies
  • Leverage: one interface, testable with plain values instead of simulated pointer events
  • Closes a real gap — InstructionCanvas.tsx has no test file of its own
Continues, not contradicts, an ADR-adjacent decision: the 2026-09-15 canvas-deepening review named this exact candidate and deliberately deferred it. It's more overdue now — the rework duplicated the pattern instead of shrinking it.

Problem: TokenDetails.tsx already holds step and token as props everywhere else, but two call sites route through an implicit "selected" mutator that depends on an unenforced invariant instead of passing the ids it already has.

Solution: call attachToToken(step.id, token.id, kind, attachment) directly at both sites, matching every other mutator call in the file.

  • Locality: one calling convention per file instead of two coexisting for no reason
  • Removes a hidden "rendered token == selected token" invariant
  • Deletion test: delete attachToSelectedTokenCore — both call sites become one-line swaps, nothing reappears
