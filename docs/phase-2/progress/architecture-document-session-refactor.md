# Architecture — document-session refactor (pre-work for Task 20)

> 📌 **Doc status: CURRENT** — one file in the
> [Phase 2 Progress Log](./README.md).

- Run via `/improve-codebase-architecture`, not a numbered task: an external audit (see [../../known-issues.md](../../known-issues.md)) had flagged `state/document.ts`'s undo/redo history, coalescing clock, and selection-repair logic as pure computation bound only to module-level signals and two module-level `let`s (`lastPushWasCoalesce`, `lastPushAt`) - one hardcoded adapter (the browser's single JS realm), so nothing could construct a second document and the module could only be exercised through a live browser. Named in `known-issues.md` as the natural prerequisite for Task 20 (Automated Testing), since there was otherwise nothing to unit-test against.
- `state/document.ts` now exports `createDocumentSession(initial?)`, constructing an independent `DocumentSession` (the document/selection/history signals, plus the coalescing clock as fields on the session object rather than closure `let`s). Every mutator/query's real implementation (`undoCore`, `addStepCore`, ...) takes a `DocumentSession` explicitly as its first argument, grouped for external callers as `sessionActions`.
- The app runs on exactly one session, `defaultSession`, created once at module load. Every existing signal/computed export (`document`, `selectedStepId`, `past`, `canUndo`, `selectedStep`, ...) is now a direct alias to `defaultSession`'s field, and every existing mutator export (`addStep`, `undo`, `moveToken`, ...) is bound to `defaultSession` via a new generic `bindActionsToSession` helper - so every one of the eight components and `state/persistence.ts` that import from `state/document.ts` needed zero changes.
- **Vitest was evaluated and deliberately not added in this pass** - see [../../known-issues.md](../../known-issues.md)'s extended vite/esbuild entry: the only `vitest` versions compatible with the pinned `vite@^5.4.11` carry a critical `@vitest/mocker` advisory, fixable only by the same major Vite upgrade already deferred there. Installed, confirmed via `npm audit`, and removed again rather than accepted, since Task 20 hadn't formally started. No unit tests exist yet; this pass only makes writing them possible - `createDocumentSession()` is the seam Task 20 needs, not the test suite itself.
