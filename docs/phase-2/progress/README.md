## Summary

Phase 2 tasks 5–23 are complete: UI Layout, Instruction Canvas, Icon Library, Live Preview, Drag-and-Drop, Touch Support, Tap-to-Insert (carried over from Phase 1), Data Persistence, Undo/Redo, Visual Validation, SVG Export, PNG Export, Print/PDF Export, JSON Export, Create Import System, Add Automated Testing, Build Responsive Layouts, Add Accessibility Features, and Convert to PWA — plus a set of product additions the user requested on top of the original task list: user-authored step titles/details, app-given token descriptions, a mobile-friendly canvas sizing scheme, and a two-stage step/token selection model with dedicated editor panels for each. `npm run lint`, `npm run typecheck`, `npm test`, and `npm run build` all pass, and every interactive flow (selection, editing, drag-and-drop, undo/redo, export/import, preview, persistence, keyboard access, mobile layout) is verified with a Playwright driver rather than by inspection alone; task 20 added a complementary Vitest unit suite (107 tests) for the pure logic that driver can't practically edge-case-test; task 21 audited and fixed three real narrow-viewport overflow bugs (see [task-21-responsive-layouts.md](./task-21-responsive-layouts.md)); task 22 audited with axe-core plus a manual keyboard walkthrough and fixed a WCAG contrast failure, a missing input label, and two real keyboard-reachability gaps - step reordering and token selection (see [task-22-accessibility-features.md](./task-22-accessibility-features.md)); task 23 added a hand-written offline service worker and app icons, catching and fixing two real service-worker bugs (a reload crash, and a cache that silently never wrote anything) before either ever shipped (see [task-23-pwa.md](./task-23-pwa.md)); a 2026-09-14 `/improve-codebase-architecture` review then validated all four of its candidates against the actual source, and three were implemented the same day - a `moveStepUp`/`moveStepDown` seam replacing a leaky splice-index primitive, a Vitest guardrail catching future drift between the exported SVG's style-baking allowlist and the stylesheet it describes, and splitting `public/sw.js`'s routing policy out from its cache-mechanics glue (see [architecture-2026-09-14-review-remediation.md](./architecture-2026-09-14-review-remediation.md)).

## Verification

- `npm run lint`, `npm run typecheck`, `npm test`, and `npm run build` pass cleanly after every change described above.
- The Playwright driver exercises, in a real browser: no console errors; canvas badges/remove controls are keyboard-focusable; the two-stage step/token select model; typing into Token details updating the canvas chip's label live; dragging a token from the picker onto a step; dragging an existing canvas token between steps; dragging a step in the list to reorder it; the Preview toggle hiding every editing control; the document (including the drag-reorder above) surviving a page reload via IndexedDB; and the mobile viewport rendering one row per step with legible, bounded icon sizes.
- Screenshots were visually reviewed (not just checked for a passing exit code) at desktop width, after drag-and-drop, in preview mode, at 390px mobile width, and (cropped/zoomed) for the connector lines and live insertion marker specifically - the only way the line-visibility bug (see [../../fixed-issues/README.md](../../fixed-issues/README.md)) was actually caught.
- The Playwright driver now also asserts a step's connector-line count matches its token count minus one, and that the insertion marker is visible mid-drag (before release), not just after.
- The Playwright driver now also attaches a Warning and a Quantity to a token via "Add to token" (the Quantity form, not a preset button), confirms the canvas chip shows two badges and Token details lists two attachments, removes one via Token details, and confirms both drop to one (`ATTACHMENTS_WORKED_END_TO_END`).
- The Playwright driver now also sets a token's own time and a step's own time via `DurationField`, confirming the step's canvas header shows the token-sum first and then the step's explicit value once set (`TIME_WORKED_END_TO_END`) - and reproduces the exact stale-state bug from the [Fixed Issues log](../../fixed-issues/README.md) (start editing, switch selection without saving, assert the new selection isn't left showing the old one's draft) for both a token switch and a step switch (`DURATION_FIELD_RESETS_PER_TOKEN`, `DURATION_FIELD_RESETS_PER_STEP`).
- The Safari-private-browsing fallback was verified directly: with `indexedDB.open` made to throw (simulating a blocked store), the app still renders and is fully usable, the warning banner appears, and no console errors are thrown.
- The Playwright driver now also confirms the Undo/Redo buttons start disabled on a fresh document (`HISTORY_BUTTONS_DISABLED_INITIALLY`), and exercises undo/redo end to end: a discrete action (adding a step) undoes/redoes as one step, typing a whole title across several keystrokes coalesces into a single undo instead of one character at a time, redo restores that coalesced edit, and both keyboard shortcuts work (`UNDO_REDO_WORKED_END_TO_END`) — verified to actually catch a regression by temporarily removing the coalescing flag and confirming the check fails, then restoring it.
- The Playwright driver now also exercises Export (captured via `page.waitForEvent("download")`): the downloaded file matches the current document and filename convention, and a non-blocking warning toast appears when the document has incomplete steps without the download being skipped (`JSON_EXPORT_DOWNLOADS_CURRENT_DOCUMENT`, `JSON_EXPORT_WARNS_ABOUT_INCOMPLETE_STEPS`) — and Import (via `setInputFiles` on the hidden file input): the confirm dialog names the right step count (`IMPORT_DIALOG_MENTIONS_STEP_COUNT`), Replace/Cancel/undo/redo all behave correctly (`IMPORT_UNDO_REDO_WORKED`), and both an unparseable file and a valid-JSON-but-wrong-shaped one are rejected with an error toast and no document change (`IMPORT_REJECTS_INVALID_FILE`) — this last check was specifically designed (a step with a real `tokens` array but one garbage-shaped token inside) so it could only pass because `migrate`'s own shape validation caught it, not because an unrelated crash elsewhere happened to be caught by the same `try`/`catch` - confirmed by breaking exactly that one check and watching the test fail, per the two related Gotchas in `SKILL.md`.
- The layout-module extraction (task 15) was verified behavior-preserving by running the full driver before touching `InstructionCanvas.tsx` and again after - identical results both times, including screenshots. Export SVG's downloaded file was checked two ways: the driver's own boolean check (`SVG_EXPORT_IS_SELF_CONTAINED_AND_STYLED`, confirming a resolved `rgb(...)` color literally appears in the file) and a direct manual read of the downloaded file's raw content, confirming real colors throughout, correct `xmlns`, and a well-formed `</svg>` close - not just trusting the boolean.
- Export PNG (task 16) is verified two ways too: the driver reads the downloaded file's raw PNG `IHDR` chunk (bytes 16-23, no image-decoding dependency needed) and confirms its pixel width/height are exactly the exported SVG's own width/height × the declared pixel density (`PNG_EXPORT_IS_RASTERIZED_AT_PIXEL_DENSITY`) - not just "some PNG downloaded," but that rasterization happened at the *declared* density specifically - and the downloaded file was read directly with the Read tool (which can display images) to visually confirm it's sharp, correctly colored, and matches the canvas exactly, not just structurally valid.
- Export PDF (task 17) is verified two ways: `PDF_EXPORT_INVOKED_WINDOW_PRINT` confirms the button actually calls `window.print()` (via a `beforeprint` listener, since there's no downloaded file and no scriptable dialog to inspect), and `PRINT_STYLESHEET_ISOLATES_READONLY_CANVAS` (via `page.emulateMedia({ media: "print" })`) confirms the toolbar and the whole editor grid are hidden, the hidden export canvas is switched back into visible flow, its SVG still has its step cards rendered, and it carries none of the editable canvas's remove-button markup. The rendered print layout was also visually confirmed with a full-page screenshot taken under print media emulation - the toolbar, panels, and toasts are gone and only the numbered step cards remain, matching what a real "Save as PDF" would produce.
- The document-session refactor was verified behavior-preserving, not by a new unit test (none exist for it - see task 20), but by a full clean run of the Playwright driver against the refactored code: all 35 checks passed with `CONSOLE_ERRORS_COUNT=0`, identical to pre-refactor runs, confirming every consumer of `state/document.ts` kept working unchanged via the default-session-bound exports.
- The drag-and-drop protocol collapse was verified the same way: a full clean driver run after the change, all 35 checks passing with `CONSOLE_ERRORS_COUNT=0`, including every drag-specific check (token-via-picker, token-between-steps, step reorder, both forward-drag regression checks, and the mid-drag insertion marker).
- Task 20's 107 new Vitest tests all pass (`npm test`), and a final full Playwright driver run after adding them still passes all 35 checks with `CONSOLE_ERRORS_COUNT=0` - confirming the new devDependency/config files have no effect on the shipped app (the production bundle size is unchanged). Several of the trickiest new unit tests (coalescing, the forward-move index adjustment, the token-category drift regression test) were each confirmed to actually fail when the code they cover was temporarily broken, not just pass by construction - the same discipline already applied to the Playwright checks above.
- Task 22 added an `axe-core` scan (WCAG rule violations) to the Playwright driver at three states - the populated main editor, the Import confirm dialog open, and the 390px mobile viewport - all reporting zero violations, plus checks that a step can be reordered via the new keyboard-only Move up/down buttons (and that they're disabled at the list's boundaries), that a token can be selected via keyboard through `StepDetails`' token list, and that the Import dialog focuses Cancel on open, traps Tab between its two buttons, and closes on Escape with the document left untouched.
- Task 23 added a new, separate script (`.claude/skills/run-instruction-builder/pwa-check.mjs`) rather than extending `driver.mjs` - the service worker it verifies is deliberately never registered against the dev server `driver.mjs` drives, only a real production build. Run against `npm run build && npm run preview`, it confirms the manifest and all three app icons are reachable, that the service worker actually takes control of the page, that a simulated second visit populates the runtime cache with the page shell and hashed assets, and that the app still loads and renders with the browser context fully offline - the actual point of the task, and the thing that caught both bugs documented above.
- The `reorderSteps` seam refactor was verified by a full clean driver run (39/39 checks, `CONSOLE_ERRORS_COUNT=0`) - `STEP_REORDERED_VIA_KEYBOARD`/`STEP_MOVE_BUTTONS_DISABLED_AT_BOUNDARIES` (task 22's own checks) now exercise `moveStepUp`/`moveStepDown` instead of raw `reorderSteps` calls without their own behavior changing - plus 5 new Vitest tests (113 total, up from 107) covering the swap, both boundary no-ops, and an unknown-id no-op. The export style-baking guardrail (`svg-export.test.ts`) was confirmed to actually catch drift, not just pass by construction, by temporarily adding an untracked CSS property to `global.css` and watching it fail before reverting. The `sw.js` policy/glue split was verified behavior-preserving via `pwa-check.mjs` against a fresh production build - identical results (manifest/icons reachable, service worker takes control, runtime cache populates, app loads fully offline) before and after.
