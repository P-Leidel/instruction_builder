# Task 15 — SVG Export

> 📌 **Doc status: CURRENT** — one file in the
> [Phase 2 Progress Log](./README.md).

- **Layout extraction first, export second:** before building export, the roughly 250 lines of pure geometry math that lived inside `InstructionCanvas.tsx` (`chipPosition`, `stepHeight`, `widestRowWidth`, `buildConnectors`, `insertionMarkerPosition`, plus the layout constants and the per-step `cardY`/`height`/`chipsPerRow` cursor math from the render function itself) moved into a new `lib/canvas-layout.ts`, behind one entry point: `computeCanvasLayout(steps, isDesktop)` returns `{ layouts, totalHeight, canvasWidth }`. `InstructionCanvas` now only renders what that function returns - a purely mechanical, behavior-preserving refactor, confirmed by running the full Playwright driver before writing any export code and again after, with identical results. This was prep work flagged by an external architecture audit (see [../../known-issues.md](../../known-issues.md)) and folded into this task rather than done separately, since building export against the canvas as it stood would have meant either scraping rendered DOM geometry or re-deriving it a second, independent way.
- **Export renders from the same source, not a second one:** `App` keeps one extra, always-mounted `InstructionCanvas readOnly` instance around permanently, hidden via a new `.app__export-canvas` CSS rule (`position: absolute; width: 0; height: 0; overflow: hidden` - not `display: none`, so it keeps rendering normally, just clipped from view and out of page layout/scroll). Export SVG serializes *that* element's own live `<svg>` DOM node - never a from-scratch re-render, and never the visible editable canvas, which carries editing-only affordances (remove buttons, selection outlines) that shouldn't end up in a downloaded file.
- **Bug found and fixed before shipping:** a plain `XMLSerializer().serializeToString(svg)` on that node - the originally planned approach, per `docs/project-plan.md`'s Export Strategy - captures markup only, never the CSS classes (`global.css`) that give the canvas any color or font at all. Confirmed by testing it directly: the output had correct shapes/positions but rendered as black-on-white/invisible, since every fill/stroke comes from a class resolved against `:root`'s custom-property design tokens. `lib/svg-export.ts`'s `bakeComputedStyles` fixes this by cloning the live node and copying each element's *resolved* `getComputedStyle` values (fill, stroke, stroke-width, stroke-dasharray, stroke-linejoin, stroke-linecap, color, font-family, font-size, font-weight, font-variant-numeric) onto the clone as an inline `style` attribute before serializing - see the [Fixed Issues log](../../fixed-issues/svg-export-unstyled-shapes.md) for the full writeup.
- The download itself reuses the exact `Blob`/object-URL/`<a download>` mechanic JSON export already used - factored out as `downloadBlob` in `lib/document-file.ts` (also now exports `slugify`) rather than duplicated a second time, since a third format (PNG, task 16) is already known to need the same mechanic next.
- **Task 14 link, same as JSON export:** clicking Export SVG also runs `validateDocument` first and shows the same non-blocking incomplete-steps warning toast.
- The toolbar's single "Export" button is now "Export JSON" and "Export SVG" side by side, since there are now two formats to choose from.
