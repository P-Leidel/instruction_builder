Split the service worker's routing policy from its execution glue

public/sw.js

Problem: the fetch handler is its own interface — routing policy (same-origin filter, the only-if-cached passthrough guard, network-first-vs-cache-first) and execution glue (clone timing, waitUntil wrapping) sit in the same 35 lines with nothing testable in isolation.

Solution: pull the routing decision out as a pure function of a Request's properties; keep one small executor that owns clone/waitUntil/cache-write mechanics exactly once.

Before — shallow

fetch listener (interface = implementation)
nothing left underneath

routing + clone timing + waitUntil, all inline. No pure function to hand a mock Request to.

After — deep

chooseStrategy(request) — pure, unit-tested
executor: clone · waitUntil · cache.match/put
(the only place body-consumption bugs can hide)

small interface, deep implementation behind it

  R[Request] --> CS["chooseStrategy(request)
pure · vitest-testable"]
  CS -->|passthrough| NET[fetch, untouched]
  CS -->|network-first| EXEC[executor]
  CS -->|cache-first| EXEC
  EXEC --> CACHE[(Cache Storage)]
  classDef pure fill:#d1fae5,stroke:#065f46,color:#065f46;

Wins

  • Leverage: routing rules become unit-testable with plain Request-shaped objects
  • Locality: body-consumption bugs can only hide in one small executor
  • Both shipped-and-caught bugs become one-line test cases
  • Interface shrinks to a return type; implementation absorbs the glue

Two real production bugs this session — service-worker-broke-every-page-reload.md, service-worker-never-actually-cached-anything.md — both only caught by deliberately driving a real browser afterward. Zero automated coverage exists today.

Give step reordering an intent-level seam instead of a splice-index primitive

src/state/document.ts · src/components/StepList/StepList.tsx

Problem: reorderSteps(fromIndex, toIndex)'s toIndex means "a splice target computed against the pre-removal array" — not "where it ends up." Two real callers (drag, and task 22's Move up/down buttons) each have to reason about that off-by-one shift themselves; the button caller needs a 6-line comment just to justify index + 2 instead of index + 1.

Solution: keep today's splice/clamp math as an unexported implementation detail; expose moveStepUp(id) / moveStepDown(id) / moveStepToIndex(id, index) as the seam in sessionActions.

Two adapters (drag, buttons) satisfying one shallow primitive is the seam test showing the primitive itself is under-abstracted — the underlying splice/clamp math (shared with moveTokenCore) is already correctly centralized and deep; only the caller-facing verb is missing.

The exported chip's style allowlist has no seam back to the stylesheet it describes

src/lib/svg-export.ts · src/styles/global.css · src/components/InstructionCanvas/InstructionCanvas.tsx · src/lib/canvas-layout.ts

Problem: "what does a token chip look like, and does it survive export?" is answered by four files with no compiler or test link between them. BAKED_STYLE_PROPS is a hand-maintained ten-item allowlist that must stay in sync with whatever global.css actually sets on .instruction-canvas__chip* — enforced by nobody.

Solution: a light guardrail, not a redesign — a test that renders one chip and diffs getComputedStyle() against BAKED_STYLE_PROPS's coverage, so a new visual property (an opacity, a gradient) fails loudly instead of silently vanishing from every exported file.

"What does a chip look like" — four unlinked layers

canvas-layout.ts — geometry constants
InstructionCanvas.tsx — chip markup, badge components
global.css — the actual visual truth ⇢ nothing reads this to check coverage
svg-export.ts BAKED_STYLE_PROPS — a ten-item guess at the layer above

Wins

  • Locality: a stylesheet/allowlist drift fails a test, not a visual diff
  • Catches the failure mode before it ships, not after (unlike the sw.js bugs)

No bug has shipped from this yet — it's the same silent-drift shape as the two sw.js bugs, one step earlier.

Top recommendation

Split the service worker's routing policy from its execution glue

Start here over the reorderSteps seam: this one has already shipped two real bugs and has zero automated coverage today, while reorderSteps is merely awkward — correct, just leaky. Pulling chooseStrategy out as a pure function is also the smallest cut of the four: one new function, one thin executor, and the two already-documented Fixed Issues entries become permanent regression tests instead of a memory of a bug that was caught once.
